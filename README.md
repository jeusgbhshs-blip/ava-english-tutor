# Ava — AI 数字人英语老师

> 开发交接：见 [`docs/handover/HANDOVER.md`](docs/handover/HANDOVER.md)；完整源码+文档包 `english-tutor-handover-20261101.zip`。交接包不包含个人 `data/`、API Key、测试截图。

> 一个跑在你电脑上的实时语音英语私教 + **数字外国朋友**：会说话、会看口型的 2D 数字人 **Ava** 陪你把英语聊起来——不限话题、像朋友一样随便聊，**听不懂或不会说时直接说中文，她会先理解再教你怎么用英文说**；聊完自动帮你总结复盘、挑出重点单词放进**今日单词表**；还可以上传英文文档/图片让她带你精读。
>
> 语音可以用浏览器自带的，也可以接入 **豆包实时语音模型 3.0**（端到端实时语音，延迟更低、声音更自然）。
> 纯本地运行，无云端账号、无第三方依赖；大模型 API Key 只保存在本机。

## 能做什么

| 模式 | 你会得到什么 |
|---|---|
| 💬 **自由对话** | **不锁话题**，像和外国朋友聊天：工作、学习、情绪、天气、旅行、美食、电影、爱好……什么都能聊。她会**先正面回应你说的内容**（不答非所问、不空泛夸"very nice"），再用英文接话、追问细节、表达自己的观点；每轮顺手给你语法纠正 + 更地道的说法 + 中文讲解。**聊完点「结束对话并总结」**，自动生成复盘 + 重点单词 + 加入今日单词表 |
| 🀄 **中文求助** | 不会说、没听懂？直接打字说中文，或点麦克风旁的 **「中文求助」** 按钮说中文：Ava 会先理解你的意思 → 给出你想说的那句英文 → 拆解意群 + 中文提示 + 「跟我读」评分，然后再继续用英文聊。*（演示模式覆盖常见中文；填 API Key 后可理解任意中文）* |
| 📒 **今日单词表** | 每次对话总结后，重点单词（音标 / 中文释义 / 英文例句 / 为什么值得记）自动进当天词表；按日期分组可回看，支持朗读；同时进入间隔复习（SRS） |
| 🎯 **单词闯关** | 6 大主题 × 48 个高频词：词卡、听发音、跟读、选择 + 拼写测验；答错的词进错词本，到期提醒复习 |
| 🎙️ **跟读打分** | 4 组句子库（日常 / 旅行 / 职场 / 发音专项），读完立刻出 0–100 分、星级、逐词红绿标注和中文发音要点 |
| 🎭 **角色扮演** | 咖啡店点单 / 机场值机 / 求职面试 / 酒店入住 4 个场景，Ava 扮演对方角色，目标句自动打勾，结束给总结 |
| 📄 **阅读讲解** | **上传英文文档或图片**（txt / md / csv / doc / docx / rtf / pptx / pdf / png / jpg / heic…），Ava 在本地提取文字 → 生成中文摘要 + 核心要点 + 重点词汇 + 理解题 → 带你一段段精读：朗读原文、逐题提问、结合原文讲解、纠正你的回答；图片走 macOS 内置 OCR，离线可用 |

额外：CEFR A1–C1 五档难度、连续打卡天数 / 总句数 / 掌握词数 / 近 7 天练习图、中文讲解可开关、实时语音识别 + 朗读，说话时嘴型 / 眨眼 / 表情跟着动。语音引擎可在「浏览器内置 / 豆包实时语音 3.0」之间切换。

## 快速开始

> 系统要求：macOS + **Google Chrome**（语音识别依赖 Chrome 内置服务；Safari 只支持打字模式）。
> 无需安装任何依赖，项目已包含可直接运行的 Node。

1. **双击 `start.command`**（或在终端执行 `bash start.command`）
2. 浏览器会自动打开 `http://127.0.0.1:5180`
3. 允许页面使用**麦克风**，点底部大按钮开始说英文（也可以直接打字）
4. 想升级成真 AI 对话：右上角 **设置** → 选一家服务商（DeepSeek / OpenAI / Kimi / 通义千问 / 本地 Ollama）→ 粘贴你的 **API Key** → **测试连接** → 保存
5. （可选）升级语音：设置 → **语音引擎** → 选「豆包实时语音 3.0」→ 填火山引擎的 **App ID + API Key**（模型版本默认 3.0，音色默认英文女声）→ **测试连接** → 保存。没开通/没填也不影响用浏览器语音

> 不填 Key 也能完整体验：应用内置**演示模式**（朋友式脚本对话 + 规则纠错 + 对话总结 + 全部单词/跟读功能），适合先熟悉流程。

关闭启动服务的终端窗口 = 停止服务。

## 语音引擎：浏览器内置 vs 豆包实时语音 3.0

| | 浏览器内置语音 | 豆包实时语音 3.0 |
|---|---|---|
| 识别/朗读 | Chrome 自带（免费，需联网） | 火山引擎端到端实时语音（更低延迟、更自然的真人感声音） |
| 需要 | Chrome + 网络 | 火山引擎账号，且已开通「端到端实时语音大模型」；App ID + API Key |
| 隐私 | 音频交给 Chrome 的语音服务 | 录音会发送到你自己的火山引擎账号；密钥只存本机 |
| 失败处理 | — | 自动回退浏览器语音并提示 |
| 教学层 | 纠错/中文求助/总结/单词表由文本模型或规则版负责 | 相同（豆包负责听说，教学反馈层不变） |

![语音引擎设置：浏览器内置 / 豆包实时语音 3.0](docs/assets/hero-voice-engine.png)

> 在设置页填好 App ID / API Key 后可点「测试连接」；模型版本和音色以你控制台实际开通的为准（默认 `3.0` / `en_female_dacey_uranus_bigtts`）。

## 你的数据放在哪

- API Key / 偏好：`data/settings.json`（权限 600，**不会**被发送到浏览器，也不会进 Git）
- 学习进度 / 生词 SRS：`data/progress.json`
- **今日单词表（按日期）**：`data/wordbook.json`
- **上传的阅读材料**：`data/docs/*.json`（只保存**提取出来的文字**，原始文件不落盘）；这些文字只会在对话时发送给你自己配置的模型 API
- **豆包实时语音凭据**：`data/settings.json` 内的 `volc` 字段（权限 600，界面只显示掩码）；启用豆包语音时，你的**录音音频**会发送到你自己的火山引擎账号
- 除了你填的模型 API（对话请求直连你选择的 OpenAI 兼容服务），应用不向任何其他服务器上传数据。

## 技术栈（零依赖）

- 后端：Node.js 24 原生 `http`，静态资源 + `/api` + SSE 流式对话；对话总结 / 阅读分析为独立非流式 JSON 调用，失败自动降级规则化结果，接口永不失败。
- 文档解析：零第三方依赖——txt 直读、docx/rtf/doc 走 macOS `textutil` + 内置 ZIP 兜底、pptx 内置 ZIP 解析、PDF 内置 FlateDecode 流解析、图片用 macOS 内置 Vision OCR（离线）。
- 前端：原生 ES Module + CSS，2D 数字人为**纯内联 SVG + CSS**（无 WebGL、无外部图片/字体）。
- 语音：浏览器 `webkitSpeechRecognition` 做英文识别，`speechSynthesis` 做美式发音朗读，`onboundary` 事件驱动口型同步。
- 大模型：任意 OpenAI 兼容接口（`/chat/completions`），服务端做反馈 JSON 抽取与总结 JSON 解析，Key 不出本机。

## 常见问题

- **麦克风没反应 / 识别不了**：确认用 Chrome 打开、地址是 `127.0.0.1`（不是 `file://`）、在地址栏左侧允许麦克风；首次允许后刷新一次更稳。
- **Ava 只会说脚本台词 / 有点答非所问？**：这是没填 Key 的演示模式（脚本式回应，界面上有「演示模式」标签，点它可直接打开设置）。填 Key 后就是真 AI，会真正理解并回答你的问题。
- **我说中文它能懂吗？**：能。文本直接输入中文即可；语音先点麦克风旁的 **「中文求助」** 按钮（识别语言切中文，说完自动切回英文）。演示模式内置 40+ 组常见中文表达的教学；填 API Key 后，任意中文 Ava 都能理解并教你怎么用英文说。
- **为什么有时 Ava 不夸我了？**：这是故意的——只有具体做得好才会表扬；有问题时她会给具体修改和练习建议，而不是"very nice"。
- **没有声音**：检查系统音量和 Chrome 站点声音权限；设置里可换英文音色（推荐 Samantha / Ava / Google US English）。
- **填了 Key 仍显示演示模式**：先点「测试连接」；Base URL 要带 `/v1`（如 `https://api.deepseek.com/v1`），模型名要和账号可用模型一致。
- **端口被占用**：服务器自动顺延 5181/5182…，以终端打印的地址为准。
- **换电脑/重装**：整个 `english-tutor/` 目录拷走即可，`data/` 里就是你的 Key、进度和单词表。
- **阅读讲解支持哪些文件？**：txt / md / csv / doc / docx / rtf / pptx / pdf / png / jpg / webp 等，单文件 ≤12MB。扫描版 PDF 提取不到文字时，直接上传它的**截图**（图片 OCR）即可。
- **上传的文件会被传走吗？**：不会。文件只在本机解析，原始文件不保存，只把提取出的文字存在 `data/docs/`；对话时会把相关文本片段发给你自己配置的模型 API。
- **豆包实时语音怎么开通？**：在火山引擎控制台开通「端到端实时语音大模型 / 豆包实时语音」，拿到 App ID 和 API Key（或 Access Token），在设置页填好并点「测试连接」；模型版本/音色按控制台给的填。
- **豆包模式为什么没声音/连不上？**：先点「测试连接」看中文错误；确认账号已开通、App ID/Key 正确、网络可访问火山引擎。失败会自动回退浏览器语音，不影响正常练习。

## ✨ v2.0：角色分层实时动效（方案 A）

三个角色现在都是「活的」：**发丝会飘、衣摆会轻摆、眨眼/视线/表情/口型实时动**——用的就是用户提供的三张原图，不做任何改画。

- **自动分层**：用 macOS Vision 自动抠出人物前景，再用模糊修复生成背景层（`web/assets/characters/layers/`），无需人工拆图。
- **2.5D 渲染**：WebGL 两遍绘制（背景层轻视差 + 前景层流动场），发丝/衣摆用多个"流动椭圆"驱动，**脸/嘴/眼区域自动保护**不参与拉扯；硬件 WebGL 实测 60fps。
- **兼容回退**：分层资源缺失/WebGL 不可用时自动回退单图引擎，不白屏。

## 🧠 v1.8：自由发散对话 + 个人知识库（DeepSeek 驱动）

### 对话不再"死板重复"
- **身份 = 视角，不是话题清单**：Elena/Maya/Hikari 的职业、城市、爱好只作为看世界的角度和语气，不再强行把话题拉回"下午茶/画廊/职场"；只有你主动问才聊。
- **对话导演**：每轮先规划（角度：细节追问/反例/联想/个人故事/观点碰撞/知识关联/情绪共鸣）再回复，并避开最近问过的问题；每轮最多 1 个问句，多给观点和故事。
- **长期记忆**：`data/memory.json` 自动记住你的兴趣、事实、聊过的话题和近况；「我的 → 兴趣标签」可手动补充，跨会话生效。
- 聊天大脑已接入 **DeepSeek（live 模式）**，不再走脚本演示库。

### 个人知识库（本地私有）
- 助手页 →「知识库」：**上传文件**（txt/md/doc/docx/rtf/pptx/pdf/图片 OCR）或**导入网页链接**，自动切块 + 生成检索摘要（异步）；
- 勾选 1–N 篇 → **围绕知识库讨论**（必须引用材料，可对比多篇）或 **发散讨论**（以材料为起点延伸到其他领域/反例/辩论）；
- 通话页会显示**引用卡片**（标题 + 片段 + 匹配度），回答里也会用 [1] 标注来源；
- 检索是「查询扩展 + BM25 + LLM 重排」混合检索，中英文都能命中；数据全部在本机 `data/kb`，不上传第三方（仅模型 API 调用）。

## 🔗 分享给朋友（额外端口，数据隔离）

想把自己的 Ava 分享给别人试用，又不想让对方看到/改到自己的学习记录、记忆和知识库——用**分享实例**：独立端口 + 独立数据目录。

### 一键启动
```bash
cd english-tutor
./scripts/share.sh          # 默认端口 5181
# 换端口：AVA_SHARE_PORT=5190 ./scripts/share.sh
```

启动后终端会打印两个地址：
- 本机：`http://127.0.0.1:5181/mobile`
- 朋友（同一 Wi-Fi）：`http://<你的局域网 IP>:5181/mobile`

### 规则
- 分享实例的数据在 `data-share/`，和你的个人数据 `data/` **完全隔离**（对话记忆、知识库、计划、复习词库都不会互相影响）；
- 首次启动会把 `data/settings.json` 里的模型/语音配置复制到分享实例，所以朋友打开就能用真 AI；朋友的使用会消耗你配置的 DeepSeek / 豆包额度；
- 重置分享数据：停掉实例后删除 `data-share/`，再启动即可；
- 停止分享：在运行终端按 `Ctrl+C`，或 `pkill -f "server.js --port 5181"`；
- 你的个人实例（5180）不受影响，可以同时开着。

### 注意：局域网 http 下「语音」会被浏览器限制
浏览器只允许在 **HTTPS 或 localhost** 下使用麦克风。朋友用 `http://192.168.x.x:5181` 打开时：
- 文字聊天、数字人画面、语音朗读（TTS）正常；
- **麦克风（说话）不可用**，页面会显示「当前地址不是安全环境」提示。
如果朋友的设备也要语音，需要 HTTPS 链接（云隧道 / 内网 HTTPS）。需要的话告诉我，我再帮你配一条 HTTPS 分享地址。

### 补充（v3.7）：修复「总喘气 / 她自己一直跟我说话」
根因（已用真实语音桥复现）：
1. PTT 录音期间客户端持续把**呼吸/停顿的静音帧**也发给服务端，服务端 VAD 连续静音 2 秒就当成"你说完了"，**用户还没点结束她就自动回复并播放语音**；她的声音又被麦克风拾到 → 自问自答/喘气声循环。
2. 客户端 start 帧**漏传了 `ptt:true`**，服务端实际用的是更短的 1.2 秒 VAD 窗口，更容易误触发。
3. v3.5 的会话预热在开始瞬间发送了几帧环境音，也可能触发无人输入的回复。

修复：
- PTT 录音改为**静音门限上行**：只有真正有声音的帧（RMS≥0.01，带 320ms 尾音）才发送；呼吸/长停顿不再发给服务端，VAD 无法在点结束前自动断句；
- start 帧补上 `ptt:true`，服务端使用 2 秒 VAD + 2.4 秒 commit 静音，正常出句；
