# Ava 后续开发与验收路线

这份路线建立在本次源码实证上。默认先完成桌面优先、本机单用户体验；多人在线形态需要单独的数据和访问控制层。此处不承诺日期或未测量的成本。

## M0 · 源码恢复与可复现基线（本轮）

交付：完整源码清单、原始基线、三份审查附录、有限缺陷修复、单元/契约回归、当前 README、CI 配置。

验收：原始 ZIP 清单一致；所有实际修复有行为验证；原始测试不能因故障被悄悄删除；真实服务/UI/发布状态分别说明。最终数字见 RECOVERY。

## M1 · 语音课堂可靠性

任务：统一连接/ready/录音/提交/播放/取消状态；解决 interrupted 事件接线；合并重复重连与看门狗；传播取消到服务端 TTS；记录连接、首帧 ASR、首字文本、首音播放耗时。补无凭据、仅实时凭据、独立 TTS 凭据不匹配的准确提示。

建议验收：

- 慢建链期间不会显示已开始有效录音；正常会话首句不需重复。
- 5 秒以上持续下行音频不触发假停滞；真正中断才进入恢复。
- 挂断/切角色后停止采音和播放，不再有旧会话覆盖新会话。
- 20 次独立首句测试、连续 5 分钟通话、断网恢复、切后台和设备切换分别记录结果；记录样本数，失败不以“设备原因”一笔带过。
- 真语音验收必须用实际目标浏览器与音频设备；假上游通过不能代替。

## M2 · 可教完整资料

任务：服务端保存 docId/段落/句子游标；优先当前句与附近上下文；规则、游标、历史和资料明确预算；将超长文本截断提示与真实保留字数统一；无模型时的增强状态不永久显示 pending。长 token TTS 分块保持顺序，按句预取和播放；避免重复请求实时合成和独立 TTS。

验收：长文末尾仍可访问；多文档材料范围明确；重连从准确当前句继续；引用/定位使用明确 id，不只依赖词语相似；任意中途停止不会继续后台合成。网页抓取、压缩解码有字节、时间和目的地址预算。

## M3 · 教学结果与数据一致

任务：将“转写匹配”与“发音测评”分开；课程状态包含练过/跳过/待复习；目标或等级变更重新生成课件版本并保留历史；统一 review/progress/wordbook 的权威来源；实际计时与固定课程时长区分。修演示分析缓存升级、记忆容量淘汰和并发更新。

验收：十四次无关回答不能标为掌握；跳过项目进入复习；已掌握单词再次出现在总结里不倒退；重新配置模型能重做旧演示分析；更换目标后课件与目标/等级一致；统计可追溯到具体活动。

## M4 · 数据可带走、可恢复

任务：统一导出/导入，包含服务端数据与浏览器书库进度；显式迁移版本；损坏文件保留和报错；容量淘汰先告知；异步写入基于版本合并。导出默认不带 Key，凭据另行配置。

验收：新机器导入后恢复课程、书库和复习；故意损坏一个 JSON 不默默覆盖原文件；中断写入恢复后有明确状态；多次导入幂等且不重置掌握情况。

## M5 · 多人在线与商业化（产品目标确认后）

任务：身份认证、用户级数据边界、模型配置权限、同源/Host 校验、SSRF 防护、连接数/文件/解压/费用预算、每用户调用统计、持久数据库与备份、运维诊断；再做会员权益、订单和支付状态。不能只部署原 server.js 就宣称支持多用户。

验收：用户 A 无法读取/修改用户 B 资料；用户无法把服务端 Key 发到任意地址；未授权请求不产生模型费用；额度/取消/重试可追踪；支付失败/重复回调不会给错权益。

## 工程实施原则

保留原生 ESM 的现有可用基础，先提取通话状态机与资料游标等高耦合逻辑。引入 TypeScript、框架或数据库时，应围绕已经验证的具体问题做有边界的迁移。每一阶段都交付源码、测试、运行方式和已知限制，不用页面数量代替完成度。
