## 2. 已修复的问题

### 2.1 语音的启动、播放进度与取消

| 原故障 | 现在的行为 | 验证范围 |
|---|---|---|
| 本地 WebSocket 一打开就开始录音，上游未 ready 的 PCM 被服务端丢弃 | 等上游 ready 后再初始化采音；初始化成功才返回启动成功 | 首次启动、暂停预热、resume、commit |
| `onAudioProgress` 没存入 handlers，长音频仍被判定没有进度 | 每个有效下行音频包都能报告时间和字节数 | 连续 251 个包、模拟 5.02 秒、替换回调 |
| ready 前断线清了超时，却未结束 connect Promise | 关闭、主动取消、协议错误和超时均结算连接等待 | 同时 connect、早关、错误帧、迟到 ready |
| 协议 ERROR 帧被事件分派漏掉，关闭回调可能重复 | 先识别错误类型；关闭通知只触发一次 | ready 前和 ready 后的鉴权/额度错误 |
| 停止时仍在等连接或麦克风权限，可能遗留启动任务 | stop 立即取消等待；迟到的媒体流关闭 tracks | 建链、ready 等待、权限弹窗等待、dispose |
| 冷启动 onReady 提前改录音状态，跳过 PTT 看门狗 | start/resume 真正成功后，统一进入录音并启动监控 | 真实 call.js 函数的冷启动、预热复用、取消 |
| 同实例 stop 后立即 start，旧 socket 的 ended 误关新会话 | 新启动清理旧定时器、旧连接与事件 | 注入旧 ended/close/error，新连接仍正常 ready |

代码：`lib/volcRealtime.js`、`web/js/doubao-voice.js`、`web/js/mobile/call.js`。20 项语音回归使用真实业务函数配合假的 WebSocket/AudioContext/getUserMedia；它们证明状态逻辑，不证明实际声音质量。

保留原来的手动 PTT 方式、约两秒重连音频缓冲以及主界面禁用浏览器 TTS 的偏好。长时间断网不保证无损；调用方和底层仍有多层超时预算，下一阶段需统一。

### 2.2 后端请求与数据稳定性

| 原故障 | 现在的行为 |
|---|---|
| 畸形 Host 导致 URL 构造抛错、服务退出 | 返回 400；同一进程继续响应正常请求 |
| 测试新模型/语音地址时可带走原先保存的 Key | 存量凭据绑定原源站；跨源要求明确提供新凭据，或明确清空 |
| 可先保存新地址再使用旧 Key 测试，绕开测试接口检查 | 设置保存执行相同绑定；语音换源时清除未重新提交的备用凭据 |
| 环境变量中的旧 Key 会覆盖刚保存的新 Key，重新出现在新地址 | 环境凭据生效时阻止跨源重绑定；同源路径调整允许 |
| 助手 onError 清空 pending 后又访问 pending.resolve | 错误和关闭都结束一次等待；旧会话关闭不影响新请求 |
| 总结再次收录已学词，把 known 重置为 new | 只给新词使用默认值，已有 SRS 状态和日程保留；显式编辑仍可生效 |
| `--open` 的启动器缺失触发异步 error，可能使服务退出 | 按平台启动并处理失败；输出手动访问地址，服务继续运行 |

代码：`server.js`、`lib/requestSafety.js`、`lib/config.js`、`lib/assistant.js`、`lib/review.js`。11 项新后端回归先在原行为下失败，再在修复后通过。全部凭据外发复现仅使用虚构 Key 和本机接收器。

macOS 继续优先打开原项目指定的 Google Chrome；Linux 使用 xdg-open，Windows 使用 explorer.exe。缺少浏览器时不自动下载或安装。

**凭据目标绑定并不等于访问权限已经补齐。** 服务仍无用户认证；公开运行前必须限制设置、资料、模型调用和语音连接的访问权限，并完善网页导入的目的地址及资源预算。

### E2E 为什么从 104 项变成 105 项

原版两处失败不应混称为业务全坏：

1. 原测试把 TXT/MD/DOCX/PDF 和 PNG 合并，默认要求 macOS Vision 在 Linux 也成功。本轮分成文档提取与图片平台契约两项：macOS 检查实际 OCR，其他系统检查明确 400 且不创建空文档。因此总数增加一项。
2. 原 grounded 检索测试还在要求旧提示词标记。当前设计是严格材料课并关闭自由聊天导演。本轮改为验证真实 fixture 标题、两句原文、只用材料、一次一句、反馈格式和角色身份；divergent 仍要求其原有导演与视角指令。

这是测试随当前设计更新，不代表补齐了跨平台 OCR，也不代表资料课的真实模型输出已验收。
