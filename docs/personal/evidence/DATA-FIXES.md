## 已完成：计划修改闭环

### 数据与行为语义

- 目标或等级实际改变时，仅把**未完成课程**标为 generating；已经完成的课程内容、等级、完成时间和进度保持原样。
- 标记更新时保留未完成课程原内容和断点。模型失败后状态为 error，可重试；不会先清空课件。
- 新课件成功替换时，将旧内容和旧断点保存到该课 `previousVersion`，新内容的当前断点设为 null，从第一步开始，避免旧短句位置跳过新教学。
- `previousVersion` 只保留最近上一版，不嵌套历史。使用课程字段白名单，不复制凭据或任意配置字段。
- 内容没有改变的更新不会提高 `generationRevision`，也不会重生成。只换老师保持课程和进度。
- 若三课已经完成，旧课程保持完整，更新目标/默认难度不会自动重写学习历史或发起无用模型任务；助手会明确提示可创建新计划。

实现位置：`lib/plans.js:112,153–208,224–248,265–279`。

### 短句和默认值

助手识别“换目标成机场值机”“改成职场英语”等明确的新主题，取消按字符串长度决定是否更新的规则。仅说“更新我的计划”时会请用户说明新目标或难度，不假称内容已经改变。等级和老师只在用户明确指定时改变，不再被当前页面默认等级/默认角色悄悄覆盖。

实现位置：`lib/assistant.js:65–80,98–127`。保持原有纯规则能力边界，没有引入新的模型分类调用。

### 防止异步旧结果覆盖

每次内容更新/重试递增 `generationRevision`。生成任务捕获当前版本，提交成功结果或写失败状态前比较版本；过时任务既不覆盖新课件，也不把新目标标失败。旧任务结束后，若同一个仍活动的计划有较新版本处于 generating，会接着生成最新版。没有启动非活动历史计划。

实现位置：`lib/lessonGen.js:76–127`。

### “我的”难度保存

`PUT /api/settings` 在设置校验及保存成功之后，同步当前活动计划等级，并更新未完成课件。设置校验失败不改计划。若计划保存失败，会尝试恢复本次设置改动并返回错误，而不会表面成功。若设置已保存，但随后模型生成失败，设置响应保留真实结果及错误说明。

在已有设置响应字段之外，计划受影响时增加：

```json
{
  "planUpdated": true,
  "plan": { "generating": true },
  "message": "难度已保存，未完成课件正在更新；已完成课程和进度保留"
}
```

缺少 Key 导致生成失败时，`plan.hasError` 为 true，message 明确说明“难度已保存，课件更新未完成……旧课件和进度已保留”。已通知前端分工采用返回 plan 与 message，不仅显示“切换成功”。

实现位置：`server.js:561–607` 附近。上述设置与计划仍为两个文件；这项失败回退不是跨文件数据库事务，不宣称消除了进程突然退出时的所有一致性风险。

## 已完成：知识库状态与反馈

与前端约定的 `enrichStatus`：

| 状态 | 真实含义 | 前端建议文案 |
|---|---|---|
| `stored` | 原文已保存，目前没有摘要任务 | 原文已入库（未生成摘要） |
| `pending` | 本进程确有摘要任务运行 | 摘要生成中 |
| `done` | 所有块都有有效摘要或关键词 | 摘要已完成 |
| `partial` | 只有部分块完成增强 | 部分摘要完成 |
| `failed` | 增强没有产生有效结果 | 摘要失败，原文可用 |

前端兼容旧 `skipped` 为 stored。只有 pending 触发轮询。

- 新文档默认 stored，无 Key 不启动后台任务，不再产生永远 pending。
- 后台任务开始时持久化 pending；同一文档重复增强请求共享同一个 Promise，不重复发起模型任务。
- 列表遇到旧版本或进程重启遗留、实际上没有任务的 pending，会根据已有摘要恢复为 stored/partial/done，保留原文。
- 结果按每块有效内容计数；空对象、空摘要、错误/越界块编号不算成功。
- 返回 `enrichedChunks`、`remainingChunks`。部分完成明确 partial，全失败 `ok:false` 并说明原文/旧摘要保留。
- 完成写回前再次检查文档存在性，避免用户删除后，迟到的增强结果重新写出该文档。

实现位置：`lib/kb.js:21,136–160,204–239,295–374`。

### HTTP 合同

`/api/kb/save-text`、`/api/kb/upload`、`/api/kb/url` 成功返回：

```json
{
  "ok": true,
  "doc": { "enrichStatus": "stored", "enrichedChunks": 0 },
  "message": "原文已入库，可按原文学习；未配置模型 Key，未生成摘要"
}
```

有任务时 doc 为 pending，message 说明摘要生成中，但原文已经可学。

`POST /api/kb/:id/enrich` 完成时：

```json
{
  "ok": true,
  "enrichStatus": "partial",
  "chunks": 6,
  "enrichedChunks": 1,
  "remainingChunks": 5,
  "message": "已生成 1/6 块摘要，其余可重试；原文仍可使用"
}
```

全部失败仍使用 HTTP 200 的业务失败合同：`ok:false`、`enrichStatus:'failed'`、计数、中文 error；不会假称成功。缺 Key/文档不存在继续 HTTP 400。重试旧资料时，如果既有摘要仍完整，但本次调用失败，响应 `ok:false`，保留旧的完整状态和摘要；错误说明明确本次失败。

实现位置：`server.js:810–916,1492–1503` 附近；前端分工已收到并接受合同。
