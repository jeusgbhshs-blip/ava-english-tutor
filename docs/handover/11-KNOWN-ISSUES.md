# 11 · 已知问题、限制与建议路线图

## A. 高优先级已知问题

### A1. 实时语音第一遍吞音 / 麦克风不稳定

- 现象：点麦克风后第一句要重说；偶发“麦克风没有发送声音”。
- 现有缓解：预热会话（`startPaused`）、PTT 门限降低到 0.0025、自动放宽门限、`resumeMic`、看门狗。
- 仍可能原因：macOS/Chrome 选错输入设备、系统静音、设备切换、首帧采集延迟。
- 建议：增加设备选择器/实时输入电平校验；服务端 ASR-only 测试；用真实设备矩阵验证。

### A2. 火山实时语音上游超时/断线

- 日志示例：`[voice] upstream error: 连接火山引擎超时：请检查网络。` / `[voice] upstream closed`。
- 现有缓解：doubao-voice 重连一次；call.js 自动恢复 + 角色 TTS 续讲；资料模式老师声音完全走独立 TTS。
- 建议：服务端增加会话健康检查、keepalive、重连策略；火山侧配额/网络监控；明确区分 quota/timeout。

### A3. system_role 8000 字符上限

- `lib/volcRealtime.buildSessionConfig` 把 persona 截到 8000 字符；资料课注入限制 5600。
- 长文无法一次全部注入实时语音；目前主要影响超长文章/超长书。
- 建议：服务端按句子游标 + 分段检索；或改为客户端 TTS 教学（老师台词由确定性逻辑生成）。

### A4. 每日书库进度只在浏览器

- `ava.book.library.v1` 存在 localStorage；换浏览器/清缓存丢失，多设备不同步。
- 建议：加用户系统（或用 server profile 区分设备）；提供进度导出/导入。

### A5. 没有账号与多租户隔离

- 服务端所有 API 共享一份数据；LAN 分享模式访问者共享 KB/词库/记忆/额度。
- 建议：至少加访问口令/只读模式；长期引入用户表/鉴权/每用户 DATA_DIR。

### A6. 旧桌面版与新手机版并存

- `/` 与 `/mobile` 两套 UI/状态/API 调用并存；新功能目前只加在 mobile。
- 建议：产品确认后删除或冻结旧桌面版，避免维护双份。

### A7. OCR 平台依赖

- `lib/docExtract.js` 图片 OCR 依赖 macOS Vision（swift/osascript）。Linux/Windows 需替换。
- 建议：接入 Tesseract/PaddleOCR/云 OCR；保留校对门槛。

### A8. 实时语音/TTS 的自动化测试不足

- `test/mock-volc-realtime.mjs` 可测协议，但真实音频质量/断流/回声需要真机验证。
- 建议：增加长语音、弱网、断线、切后台、设备切换的测试矩阵。

## B. 中低优先级/产品限制

- **无构建/无类型检查**：改动大时容易引入拼写/引用错误；建议后续引入 TypeScript 或至少 ESLint + jsdoc 检查。
- **无数据库**：JSON 文件适合本地单用户，不适合高并发/多用户；需要迁移。
- **TTS 缓存 80MB/400 文件**：自动 prune；没有按用户隔离。
- **翻译/总结异步依赖模型**：无 key 时走 demo/规则；质量有限。
- **长文本 TTS 上限 4000 字符**：整篇书不能一次读；需要按句/段队列。
- **资料课老师声音走 TTS 有额外合成延迟**：可接受但需优化预合成/缓存。
- **前端调试 API 暴露在 window**：方便 QA，但生产环境可考虑移除/限制。
- **多语言/移动端**：当前按桌面优先；手机布局虽有 CSS 但非产品目标。
- **截图/文档资产很大**：交接包已排除 docs/assets/test artifacts；产品仓库建议单独管理。

## C. 建议的 2–4 周路线图

1. **稳定语音链路**：真实设备矩阵 + 服务端健康检查 + 断线监控；把“第一遍吞音”解决到可接受。
2. **资料课服务端化**：句子游标、逐句 TTS 队列、重点词/句型绑定；摆脱实时模型自由发挥。
3. **用户/数据层**：登录/口令、每用户 DATA_DIR、书库/复习进度服务端同步。
4. **内容扩充**：再增加 6–12 本公版书/主题文章；每日推荐策略（难度/兴趣/复习）。
5. **学习闭环增强**：每周复习测、口语评分趋势、学习报告、提醒。
6. **工程化**：ESLint/类型检查、CI（API + UI）、错误上报、版本化数据迁移。
